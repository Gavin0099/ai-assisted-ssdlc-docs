# 固定網頁配色與呈現

使用 reporting repo 的 `templates/s1-assessment-web.html`，由 skill `project` 的結構化 generator 或 `render` 的舊人工入口產出同版本 HTML。不要另做一套 dashboard、導入前端框架或逐頁手寫 CSS。

本參考固定目前閱讀版的設計意圖；實際數值以共用 HTML 模板為準。使用者要求改版時改共用模板與本參考，所有新生成報告沿用同一版；已有來源報告與歷史網頁依當次授權保留。

## 配色

| 用途 | 現行共用模板色值 | 意義 |
| --- | --- | --- |
| 左側導覽 | `#122238` | 深藍底，白字／淺藍次要字 |
| 導覽選中項 | `#244a78` | 目前閱讀位置 |
| 頁面背景 | `#f2f5f9` | 淺灰藍，與白色內容區分開 |
| 內容卡片 | `#ffffff` | 摘要、指標、修正單與詳情 |
| 主要文字 | `#15243a` | 深色正文 |
| 次要文字 | `#5e6d81` | 路徑提示、數量說明 |
| 連結與主要按鈕 | `#225dcc` | 可執行的閱讀操作 |
| 邊框 | `#d9e1eb` | 卡片與表格分界 |
| 宣稱限制提醒 | `#fff8f0`／`#c88951` | 琥珀淺底及側線，提醒核准／執行邊界 |
| P1 標籤 | `#fff0e5`／`#9d4516` | 沿用來源明列的優先級 |
| 鍵盤焦點 | `#f59b43` | 可見焦點，方便鍵盤操作 |

不把 COVERED 畫成綠色完成勾選，不用配色暗示產品安全、已核准或已修好。P1 只在報告有明列時顯示；不要由 PARTIAL／weak 換算。其他現有 verdict 和證據強度也照原值顯示。

## 閱讀順序與版面

桌面左側固定三個入口，右側顯示當前內容。手機導覽改成上方，六欄表改成保留欄位名稱的逐項卡片；不能只留下簡化描述而拿掉改法或完成條件。

頁首先顯示來源版本、文件份數與當次報告狀態，再用四張指標卡顯示範圍、Task coverage、實際執行證據與 A／B／C 項目數。各數字與值來自實際來源，沒有固定七題、32 份或 weak 的預設結論。

主管摘要使用四個固定章節，入口清楚連到工程師修正單。修正單顯示六欄，提供搜尋、產品／範圍與 A／B／C 篩選；這只是閱讀分類，不建立新的 applicability verdict。

結構化流程的範圍分類只使用記錄中的 `scope_labels`；缺標籤顯示「未記錄範圍標籤」，用 ID／路徑與 A／B／C 搜尋，不由檔名推填。舊人工 reader 保留其 Pilot 名稱辨識，陌生名稱可能顯示「未分類」；不能為套篩選器改產品名稱。分類泛化另行授權。

共用頁首導覽目前保留「公司 SSDLC Pilot」字樣。不同範圍的報告仍在正文、report-id 與版本資訊清楚標示真實對象，交付時如實說明這個版型限制；不為了既有字樣把樣本或新評估稱為公司 Pilot。

點問題 ID 後顯示附錄原有八欄依據，包含具體改法與完成確認。詳情可關閉／返回修正單，亦可跳到完整附錄相應位置。附錄採可展開的完整內容，保留來源指紋與原始三份 Markdown 入口。

沒有符合篩選的項目要有清楚提示。原分類沒有項目則顯示本次未列，不能為版面湊數。字體沿用系統字型，不依賴外部字型、CDN 或自動網路請求。

## 操作與驗證

- 搜尋 ID 或文件編號，確認結果對應原修正單；測一次找不到項目的情況。
- 切換產品與 A／B／C，確認來源分類、數量與空狀態，清除篩選可回到全部。
- 開啟一個問題，確認八項依據完整、關閉能返回，附錄跳轉到正確 ID；注意長詳情與手機的按鈕可操作。
- 看桌面與手機寬度，頁面不要整體水平溢出；長技術表格可以在自己的區域捲動。
- 核對 source commit、report-id、STATUS、coverage、strength 與 HTML 來源指紋。檢查沒有 parser／JavaScript 錯誤；能測無 JavaScript 與列印樣式時使用相稱檢查。

網頁是本地閱讀 artifact。操作不寫入處理完成、核准或證據，不自動做外部部署。畫面與互動通過也不等於語意判讀正確、產品已執行或讀者已接受。
